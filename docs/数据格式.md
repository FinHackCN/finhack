# Finhack 本地数据格式规范

## 概述

Finhack项目采用多种数据存储格式来优化不同类型数据的存储和访问性能。本文档详细说明了项目中使用的各种本地数据格式，不包括SQLite数据库和缓存数据。

## 数据存储目录结构

```
data/
├── market/          # 市场数据
├── factors/         # 因子数据
├── models/          # 模型文件
├── preds/           # 预测结果
├── reports/         # 报告文件
├── cache/           # 缓存数据（因子缓存、运行时文件）
├── logs/            # 日志文件
└── running/         # 运行时数据（较少使用）
```

## 1. 市场数据格式 (market/)

### 1.1 K线数据存储

#### 目录结构

**Codebased 存储**（按股票代码分组）:
```
market/kline/codebased/
└── {market}/              # cn_stock, cn_index, cn_cb, cn_fund, hk_stock, global_fx, cn_future
    └── {freq}/            # 1d, 1m
        ├── {year}/        # 2000, 2001, ...
        │   └── {code}.csv # 如 000001.SZ.csv
        └── {year}.parquet # 年度Parquet缓存
```

**Timebased 存储**（按时间分组，主要用于1分钟数据）:
```
market/kline/timebased/
└── {market}/
    └── {freq}/
        └── {year}/{month}/{day}/
            ├── {market}_kline_merged.csv      # 合并后的K线数据
            └── {market}_kline_{source}.csv    # 特定数据源的数据（iquant, qmtht等）
```

**说明**:
- **codebased**: 适合读取单个股票的完整历史数据
- **timebased**: 适合读取某一天的全部股票数据（主要用于1分钟数据）

---

**其他目录**:
```
market/
├── reference/        # 参考数据（股票列表、复权因子等）
└── fundamental/      # 基本面数据
```

#### 数据格式

**CSV文件格式**:
- **存储格式**: CSV文件（**无header行**）/ Parquet文件（缓存）
- **命名规则**: `{code}.csv`（codebased）/ `{market}_kline_merged.csv`（timebased）/ `{year}.parquet`
- **列顺序**（固定）: `time,code,open,high,low,close,volume,amount`
- **时间格式**: `YYYY-MM-DD HH:MM:SS+08:00`（所有市场统一格式）
- **示例**:
  ```
  2024-10-17 09:30:00+08:00,000537.SZ,8.91,8.99,8.91,8.94,275900.0,2467429.0
  ```

**注意**: CSV文件**无header行**，读取时需要显式指定列名:
```python
df = pd.read_csv(file_path, header=None,
                 names=['time', 'code', 'open', 'high', 'low', 'close', 'volume', 'amount'])
```

#### Parquet缓存格式（优化性能）

**文件路径**: `market/kline/codebased/{market}/{freq}/{year}.parquet`


**生成方式**:
```bash
# 生成Parquet缓存
finhack kline cache --vendor=default --background --project_path=/path/to/project
```

**智能读取策略**（按优先级）:

1. **Parquet策略**: 单年份查询且代码数量 > 100
   - 条件: `len(years) == 1 and len(codes) > 100`
   - 优势: 列式存储，批量读取性能高

2. **Timebased策略**: 1分钟数据且代码数量 > 50
   - 条件: `freq == '1m' and len(codes) > 50`
   - 适用: 读取某天全部股票的1分钟数据
   - 优势: 按时间分区，减少文件读取

3. **Codebased策略**: 其他情况（默认）
   - 适用: 日线数据、少量代码查询、跨年份查询
   - 优势: 按股票分区，适合读取单股票历史数据

**注意**:
- 跨年份查询**不使用** Parquet（避免读取多个大文件）
- 1分钟数据优先使用 timebased 存储

## 2. 因子数据格式 (factors/)

### 2.1 矩阵型因子 (matrix/)

#### 目录结构
```
factors/matrix/
└── cn_stock/
    └── 1d/
        └── YYYY/          # 按年分组
            └── {code}/    # 按股票代码分组
                └── {factor}_{shift}.pkl  # 因子数据，如 PE_0.pkl
```

#### 数据格式
- **存储格式**: Pickle文件 (.pkl)
- **文件命名**: `{factor}_{shift}.pkl`（如 `PE_0.pkl`、`MA5_1.pkl`）
  - `shift` 表示向前偏移的天数，0表示当日数据，1表示1日前数据
- **数据类型**: pandas.Series
- **索引**: MultiIndex (code, time)
- **数值类型**: float64

**示例**:
```
factors/matrix/cn_stock/1d/2019/000537.SZ/
├── PE_0.pkl
├── MA5_0.pkl
├── MA10_1.pkl
└── ...
```

### 2.2 向量型因子 (vector/)

#### 存储格式
- **文件**: `{market}/{freq}/{factor_name}.pkl`
- **数据类型**: pandas.DataFrame
- **索引**: MultiIndex (time, code)

### 2.3 分组因子 (group/)

#### 存储格式
- **数据类型**: 分组标识和权重信息
- **格式**: Pickle文件

### 2.4 缓存因子文件

**路径**: `data/cache/factors/{market}/{freq}/factors_{hash}.pkl`

**说明**:
- 缓存多因子组合的 DataFrame，避免重复计算
- 使用 MD5 哈希作为文件名
- 当因子组合或参数变化时，自动重新生成

### 2.4 MySQL项目特有格式

#### 单因子数据格式
```
factors/
├── single_factors/           # CSV格式单因子
├── single_factors_parquet/   # Parquet格式单因子
├── single_factors_pkl/       # Pickle格式单因子
│   └── _tmp/                # 临时文件目录
├── single_factors_pkl_tmp/   # 临时处理目录
├── code_factors/            # 按代码分组的因子
└── date_factors/            # 按日期分组的因子
```

#### Parquet格式特点
- **压缩**: 支持多种压缩算法
- **列式存储**: 提供更好的查询性能
- **数据类型**: 保持数据类型信息

#### Pickle格式特点
- **序列化**: Python原生序列化格式
- **数据完整性**: 保持pandas数据结构完整
- **处理流程**: CSV → Pickle → 缓存

## 3. 报价数据格式 (quote/)

### 3.1 目录结构
```
quote/
├── stock/
│   ├── SH/              # 上海证券交易所
│   │   └── {code}/
│   │       ├── daily/   # 日线数据
│   │       ├── minutely/# 分钟线数据
│   │       └── tick/    # 逐笔数据
│   └── SZ/              # 深圳证券交易所
│       └── {code}/
├── crypto/              # 加密货币
├── forex/               # 外汇
├── future/              # 期货
└── option/              # 期权
```

### 3.2 数据格式
- **存储格式**: Pickle文件 (.pkl)
- **数据结构**: pandas.DataFrame
- **时间频率**: 
  - daily: 日线数据
  - minutely: 分钟线数据
  - tick: 逐笔数据

## 4. 模型文件格式 (models/)

### 4.1 LightGBM模型

#### 文件格式
- **命名**: `lgb_model_{md5hash}.txt`
- **格式**: LightGBM原生文本格式
- **内容结构**:
  ```
  tree
  version=v4
  num_class=1
  num_tree_per_iteration=1
  ...
  Tree=0
  num_leaves=64
  ...
  feature_importances:
  {feature_name}={importance}
  ...
  parameters:
  [boosting: gbdt]
  [objective: regression]
  ...
  ```

### 4.2 模型元数据
- **存储格式**: JSON或Pickle
- **包含信息**: 训练参数、特征列表、性能指标

## 5. 预测结果格式 (preds/)

### 5.1 文件格式
- **命名**: `{algorithm}_model_{hash}_pred.pkl`（如 `lgb_model_{hash}_pred.pkl`）
- **数据类型**: pandas.DataFrame
- **索引**: MultiIndex (code, time)
- **字段**: 预测值（pred）

### 5.2 缓存机制
- **缓存文件**: 自动生成基于参数的哈希文件名
- **格式**: Pickle文件
- **更新策略**: 基于模型和数据更新时间

## 6. 报告文件格式 (reports/)

### 6.1 HTML报告

#### 主报告文件
- **文件**: `index.html`
- **格式**: Jinja2模板渲染的HTML
- **功能**: 回测结果概览表格
- **依赖**: jQuery, DataTables

#### 静态资源
```
reports/static/
├── css/                 # 样式文件
├── js/                  # JavaScript文件
├── images/              # 图片文件
│   └── {instance_id}.png  # 回测结果图表
├── rqalpha/            # RQAlpha相关文件
└── trader/             # 交易相关文件
    └── {instance_id}.html  # 详细回测报告
```

### 6.2 图表格式
- **格式**: PNG图片
- **命名**: `{instance_id}.png`
- **内容**: 回测结果可视化图表

## 7. 运行时数据格式

### 7.1 Cache 目录（主要缓存位置）

**路径**: `data/cache/`

**子目录**:
```
cache/
├── factors/              # 因子缓存
│   └── {market}/{freq}/
│       └── factors_{hash}.pkl
├── runtime/              # 运行时生成的Python文件
│   ├── constant.py       # 路径常量定义
│   └── global_var.py     # 全局变量定义
└── *.pkl                 # 其他临时pickle文件
```

**说明**:
- `cache/factors/`: 缓存多因子组合的DataFrame
- `cache/runtime/`: 运行时生成的Python配置文件
- 临时pickle文件: 用于中间计算结果缓存

### 7.2 Running 目录

**路径**: `data/running/`
- 临时数据文件，较少使用
- **格式**: Pickle文件 (.pkl)
- **命名**: `r_{hash}.pkl`

### 7.3 运行时脚本
- **格式**: Python脚本 (.py)
- **功能**: 数据处理和调试

## 8. 数据访问模式

### 8.1 缓存策略
- **内存缓存**: 使用Redis或本地缓存
- **文件缓存**: Pickle格式快速读写
- **分层缓存**: 内存 → 文件 → 数据库

### 8.2 数据读取优化
- **并行处理**: 使用ThreadPoolExecutor
- **批量读取**: 减少I/O操作
- **延迟加载**: 按需加载数据

### 8.3 存储优化
- **分区存储**: 按时间/代码分区
- **压缩存储**: Parquet格式提供压缩
- **索引优化**: MultiIndex提供快速查询
