# Finhack 本地数据格式规范

## 概述

Finhack项目采用多种数据存储格式来优化不同类型数据的存储和访问性能。本文档详细说明了项目中使用的各种本地数据格式，不包括SQLite数据库和缓存数据。

## 数据存储目录结构

```
data/
├── market/          # 市场数据
├── factors/         # 因子数据
├── models/          # 模型文件
├── preds/           # 预测结果
├── reports/         # 报告文件
├── logs/            # 日志文件
└── running/         # 运行时数据
```

## 1. 市场数据格式 (market/)

### 1.1 K线数据存储

#### 目录结构
```
market/
├── kline/
│   ├── codebased/    # 按代码分组的K线数据
│   │   ├── cn_stock/1d/YYYY/  # 中国股票日线数据，按年分组
│   │   ├── cn_index/1d/YYYY/  # 中国指数日线数据
│   │   ├── cn_cb/1d/YYYY/     # 可转债日线数据
│   │   ├── cn_fund/1d/YYYY/   # 基金日线数据
│   │   ├── hk_stock/1d/YYYY/  # 港股日线数据
│   │   └── global_fx/1d/YYYY/ # 全球外汇日线数据
│   └── timebased/    # 按时间分组的K线数据
│       └── [同上结构]
├── reference/        # 参考数据
└── fundamental/      # 基本面数据
```

#### 数据格式
- **存储格式**: CSV文件
- **命名规则**: `{symbol}_{freq}.csv`
- **时间格式**: 
  - 中国股票/指数/可转债/基金: `YYYY-MM-DD 09:30:00+08:00`
  - 港股: `YYYY-MM-DD 10:00:00+08:00`
  - 全球外汇: `YYYY-MM-DD 00:00:00+08:00`

## 2. 因子数据格式 (factors/)

### 2.1 矩阵型因子 (matrix/)

#### 目录结构
```
factors/matrix/
└── cn_stock/
    └── 1d/
        └── YYYY/          # 按年分组
            └── {code}/    # 按股票代码分组
                ├── index.pkl      # 索引文件
                ├── {factor1}.pkl  # 因子1数据
                ├── {factor2}.pkl  # 因子2数据
                └── ...
```

#### 数据格式
- **存储格式**: Pickle文件 (.pkl)
- **数据类型**: pandas.Series
- **索引**: MultiIndex (code, time)
- **数值类型**: float64

#### 索引文件格式 (index.pkl)
```python
# DataFrame结构
columns: ['code', 'time']
index: DatetimeIndex
```

### 2.2 向量型因子 (vector/)

#### 存储格式
- **文件**: `{market}/{freq}/{factor_name}.pkl`
- **数据类型**: pandas.DataFrame
- **索引**: MultiIndex (time, code)

### 2.3 分组因子 (group/)

#### 存储格式
- **数据类型**: 分组标识和权重信息
- **格式**: Pickle文件

### 2.4 MySQL项目特有格式

#### 单因子数据格式
```
factors/
├── single_factors/           # CSV格式单因子
├── single_factors_parquet/   # Parquet格式单因子
├── single_factors_pkl/       # Pickle格式单因子
│   └── _tmp/                # 临时文件目录
├── single_factors_pkl_tmp/   # 临时处理目录
├── code_factors/            # 按代码分组的因子
└── date_factors/            # 按日期分组的因子
```

#### Parquet格式特点
- **压缩**: 支持多种压缩算法
- **列式存储**: 提供更好的查询性能
- **数据类型**: 保持数据类型信息

#### Pickle格式特点
- **序列化**: Python原生序列化格式
- **数据完整性**: 保持pandas数据结构完整
- **处理流程**: CSV → Pickle → 缓存

## 4. 模型文件格式 (models/)

### 4.1 LightGBM模型

#### 文件格式
- **命名**: `lgb_model_{md5hash}.txt`
- **格式**: LightGBM原生文本格式
- **内容结构**:
  ```
  tree
  version=v4
  num_class=1
  num_tree_per_iteration=1
  ...
  Tree=0
  num_leaves=64
  ...
  feature_importances:
  {feature_name}={importance}
  ...
  parameters:
  [boosting: gbdt]
  [objective: regression]
  ...
  ```

### 4.2 模型元数据
- **存储格式**: JSON或Pickle
- **包含信息**: 训练参数、特征列表、性能指标

## 5. 预测结果格式 (preds/)

### 5.1 文件格式
- **命名**: `model_{model_id}_pred.pkl`
- **数据类型**: pandas.DataFrame
- **索引**: MultiIndex (code, time)
- **字段**: 预测值、置信度等

### 5.2 缓存机制
- **缓存文件**: 自动生成基于参数的哈希文件名
- **格式**: Pickle文件
- **更新策略**: 基于模型和数据更新时间

### 7.1 临时数据文件

### 7.2 运行时脚本
- **格式**: Python脚本 (.py)
- **功能**: 数据处理和调试

## 8. 数据访问模式

### 8.1 缓存策略
- **内存缓存**: 使用Redis或本地缓存
- **文件缓存**: Pickle格式快速读写
- **分层缓存**: 内存 → 文件 → 数据库

### 8.2 数据读取优化
- **并行处理**: 使用ThreadPoolExecutor
- **批量读取**: 减少I/O操作
- **延迟加载**: 按需加载数据

### 8.3 存储优化
- **分区存储**: 按时间/代码分区
- **压缩存储**: Parquet格式提供压缩
- **索引优化**: MultiIndex提供快速查询

## 9. 数据格式选择指南

### 9.1 格式对比
| 格式 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| CSV | 通用性强、可读性好 | 无数据类型、性能较低 | 原始数据、参考数据 |
| Pickle | 保持数据结构、读写快 | Python专用、版本兼容 | 因子数据、缓存数据 |
| Parquet | 压缩率高、查询快 | 需要额外库、复杂度高 | 大规模因子数据 |
| JSON | 结构化、跨语言 | 文件较大、无数据类型 | 配置文件、元数据 |

### 9.2 选择原则
- **原始数据**: 使用CSV格式，便于查看和处理
- **因子数据**: 使用Pickle或Parquet，优化性能
- **缓存数据**: 使用Pickle，保持数据完整性
- **配置数据**: 使用JSON或CONF，便于修改
- **报告数据**: 使用HTML+静态资源，便于展示

## 10. 数据维护建议

### 10.1 清理策略
- **定期清理**: 删除过期的临时文件
- **压缩归档**: 历史数据压缩存储
- **索引重建**: 定期重建索引文件

### 10.2 备份策略
- **增量备份**: 仅备份变更数据
- **分层备份**: 重要数据多层备份
- **异地备份**: 关键数据异地存储

### 10.3 监控指标
- **存储空间**: 监控磁盘使用率
- **访问性能**: 监控数据读取速度
- **数据完整性**: 定期校验数据一致性
