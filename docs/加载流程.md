# FinHack 框架加载流程（简版）

## 1. 命令行入口

**入口点**：`finhack=finhack.core.command.finhack:main`

**执行流程**：
```
Core() → load_module() → [fork后台?] → do_action()
```

**基础参数**：`module`, `action`, `--vendor`, `--background`, `--project_path`, `--section`, `--log_level`

---

## 2. Core 初始化流程

### 2.1 初始化顺序

| 步骤 | 方法 | 说明 |
|------|------|------|
| 1 | `load_help_text()` | 加载 `help.conf`（项目 → 模板） |
| 2 | `generate_args()` | 创建 ArgumentParser，解析基础参数 |
| 3 | `check_project()` | 处理 `project create/renew` |
| 4 | `check_env()` | 检查 `.proj` 文件验证项目目录 |
| 5 | `refresh_runtime()` | 生成 `constant.py` / `global_var.py` |
| 6 | `append_args()` | 按优先级加载配置参数 |
| 7 | `generate_global()` | 设置 `global_var.args/hash/pid` |
| 8 | `init_logger()` | 初始化日志系统 |

### 2.2 关键方法说明

**`refresh_runtime()`**：将 `.conf` 模板中的 `{BASE_DIR}` / `{FRAMEWORK_DIR}` 替换为实际路径

**`append_args()`**：
- 支持 `key=value` 格式命令行参数
- 命令行参数优先级 > 配置文件

## 3. 配置加载机制

### 3.1 参数优先级（从高到低）

| 优先级 | 来源 | 格式示例 |
|--------|------|----------|
| 1 | 命令行 key=value | `cash=100000` |
| 2 | 命令行 --key | `--cash 100000` |
| 3 | `{module}.conf [section]` | 指定 `--section=xxx` 时加载 |
| 4 | `{module}.conf [args]` | 模块默认配置 |
| 5 | `args.conf [module-vendor-action]` | 最具体配置 |
| 6 | `args.conf [module-vendor]` | 供应商配置 |
| 7 | `args.conf [module]` | 模块配置 |
| 8 | `args.conf [global]` | 全局默认配置 |

**规则**：命令行参数会覆盖配置文件中的同名参数。

### 3.2 配置段命名规则

```ini
[global]                    # 全局默认
[trader]                    # 模块级别
[trader-qmt]               # 模块+供应商
[trader-qmt-run]          # 模块+供应商+动作
```

### 3.3 key=value 参数实现

通过 `setattr(args, key, value)` 注入到 args 对象，绕过 argparse 的 `--key value` 格式限制。

## 4. 模块加载机制

### 4.1 加载流程

```
Core.load_module()
  ├─ ClassLoader.get_module(                      # 加载 Loader
  │    user: {project}/loader/{module}_loader.py  # 用户自定义
  │    sys:  finhack.core.loader.{module}_loader  # 系统默认
  │  ) → 失败抛出异常
  └─ 确定 class_name → 实例化 Loader

BaseLoader.__init__()
  ├─ ClassLoader.get_module(                      # 加载业务模块
  │    user: {project}/{module}/{vendor}/{vendor}_{module}.py
  │    sys:  finhack.{module}.{vendor}.{vendor}_{module}
  │  ) → 失败抛出异常
  └─ getattr(module, class_name) → 实例化业务类
```

### 4.2 ClassLoader

- **位置**：`finhack/core/loader/class_loader.py`
- **优先级**：用户模块 → 系统模块 → **抛出异常**
- **注意**：不会自动回退到 `base_loader`

### 4.3 BaseLoader

- **业务模块路径**：`finhack.{module}.{vendor}.{vendor}_{module}`
- **类名规则**：`{Vendor.capitalize()}{Module.capitalize()}`（如 `BacktestTrader`）
- **错误处理**：类不存在时输出诊断信息并 `exit()`
- **`stop` 方法**：通过 PID 文件和进程名终止后台任务

---

## 5. 执行流程

```python
def do_action():
    loader = module.Loader(args)              # 获取 Loader 类
    method = loader.action                    # 优先从 Loader 获取
          or loader.klass.action              # 否则从业务类获取
    method()                                  # 执行
```

---

## 6. 运行时系统

| 文件 | 内容 |
|------|------|
| `constant.py` | `FRAMEWORK_DIR`, `BASE_DIR`, `DATA_DIR`, `LOGS_DIR` 等常量 |
| `global_var.py` | `args`, `pid`, `hash`, `module_name`, `action_name` 等全局变量 |

---

## 7. 日志系统

- **级别控制**：`--log_level=DEBUG/INFO/WARNING/ERROR`（默认 INFO）
- **日志路径**：`LOGS_DIR/{module}/{vendor}/{action}.log`

---

## 8. 使用示例

### 8.1 创建项目
```bash
finhack project create --project_path=/path/to/project
```

### 8.2 回测交易
```bash
finhack trader run --vendor=backtest --strategy=demoStrategy
```

### 8.3 带参数回测（key=value 格式）
```bash
finhack trader run --vendor=backtest cash=100000 start_time=2024-01-01
```

### 8.4 停止后台任务
```bash
finhack trader stop --vendor=backtest
```

## 9. 自定义扩展

### 9.1 自定义 Loader

**路径**：`{project}/loader/{module}_loader.py`

```python
from finhack.core.loader.base_loader import BaseLoader

class TraderLoader(BaseLoader):
    def run(self):
        # 自定义运行逻辑
        self.klass.run()
```

### 9.2 自定义业务模块

**路径**：`{project}/{module}/{vendor}/{vendor}_{module}.py`

```python
class BacktestTrader:  # 类名 = Vendor + Module
    def __init__(self, args):
        self.args = args

    def run(self):
        # 自定义交易逻辑
        pass
```

**类名规则**：`{Vendor.capitalize()}{Module.capitalize()}`

## 架构概览

```
┌─────────────────────────────────────────┐
│  命令行入口 (finhack.core.command.finhack) │
└─────────────────┬───────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│  Core 类                                 │
│  ├── load_help_text()                   │
│  ├── generate_args()                    │
│  ├── check_env()                        │
│  ├── refresh_runtime()  → constant.py   │
│  ├── append_args()      → 配置优先级    │
│  ├── generate_global()  → global_var.py │
│  └── init_logger()                      │
└─────────────────┬───────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│  ClassLoader (core/loader/class_loader) │
│  用户模块 → 系统模块 → 抛出异常          │
└─────────────────┬───────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│  Loader (BaseLoader 或自定义)            │
│  └── 加载业务模块 → 实例化业务类         │
└─────────────────┬───────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│  执行业务逻辑 (do_action)                │
└─────────────────────────────────────────┘
```

## 关键要点

1. **用户优先**：模块加载优先使用用户自定义，其次系统默认
2. **严格失败**：模块不存在时**抛出异常**，不会自动回退
3. **参数覆盖**：命令行 `key=value` 优先级最高
4. **命名规范**：业务类名必须是 `VendorModule` 格式
5. **配置分层**：`[global]` → `[module]` → `[module-vendor]` → `[module-vendor-action]`
